# dsh-plugin-feishu-im

[![npm](https://img.shields.io/npm/v/dsh-plugin-feishu-im.svg)](https://www.npmjs.com/package/dsh-plugin-feishu-im)
[![license](https://img.shields.io/npm/l/dsh-plugin-feishu-im.svg)](./LICENSE)

DeepSeek Harness 的飞书 IM 通道：在 DSH Web 的「设置 → 飞书 IM」里扫码创建一个专属飞书机器人，
把任务进展、审批请求、提问推到飞书，并允许在飞书里直接指挥 DSH。

## 现在能做什么

| 能力 | 行为 |
|---|---|
| 连接 | 扫码创建专属飞书应用（自动带上收发消息权限），或手动填 App ID / App Secret |
| 任务通知 | 任何会话一轮结束时推一张卡片：结论 + 用时，失败时带错误原因 |
| 审批 | 工具需要授权时推一张卡片，「允许一次 / 拒绝」；点完 DSH 继续跑 |
| 提问 | `ask_user_question` 的单选题变成按钮，点完答案回到会话 |
| 进度指示 | 收到消息后给你那条消息加 `Typing` 徽标，处理完撤掉；失败换成 `CrossMark` |
| 渲染 | 消息以 **卡片 JSON 2.0** 发送：标题、引用、代码块、markdown 表格都能渲染；超长内容按段分页而不是截断 |
| 指挥 | 在飞书里发消息 → 进 DSH 会话执行 → 结果回传到同一个飞书对话 |
| 命令 | `/new` 新会话、`/stop` 停下当前任务、`/id` 看当前会话、`/help` |
| 记录一致 | 飞书上的授权/回答走和网页点击相同的 waterfall，`approval/asked` + `approval/decided` 与提问回复按同一种方式落日志 |

审批与提问默认**只走飞书**：宿主不再把同一条请求转给网页，所以在飞书答完就是最终结果，
不会留下一个还在等你的网页提示。原理是网页端的待处理提示只能由“点击”或“本轮结束”解除，
宿主没有撤销它的接口——要保证飞书答复是最终的，就只能不向网页发起。

设置页的「网页与飞书同时询问」打开后恢复并行模式：两边都弹，谁先回答用谁，但飞书先答时，
网页那条提示要等本轮结束才消失。桌面工作时建议打开。

**等待上限**：设置页里可以直接填 **1–120 分钟**，或打开「永不超时」。超过时限还没人点飞书卡片时，
插件会先把卡片 PATCH 成“⏱ 已转回 DSH 网页继续询问”（按钮消失，之后再点会提示已失效），
然后把请求交回 DSH 的网页答案器——也就是你离开工位太久时，它不会一直悬着。

⚠️ 这段时间里 **DSH 网页不会弹原生的选择窗口**：独占模式下请求只存在于飞书，网页端保持静默，
直到超时转回。设置页里对这一点有明确提示。

“切换会话”不额外发消息：**只改提问卡片本身**。

- 点「输入你的答案」→ 提问卡片原地变成「⌨️ 等待你输入答案」，写明有效时长；
- 文字答案送达 → 同一张卡变成「✅ 已作答」，`问题：答案（输入）`；
- 超时 → 同一张卡变成「⏱ 已超时」，`问题：(未作答)` + 已转回 DSH 网页端。

聊天里不会出现「已进入输入答案」「已收到你的答案」「超时了」这类旁白消息，状态都在那张卡上。

| 时机 | 消息 |
|---|---|
| 点「输入你的答案」 | 提问卡片改写为 ⌨️ 等待你输入答案（N 分钟内有效） |
| 答案被接住 | 提问卡片改写为 ✅ 已作答：`问题：答案（输入）` |
| 超时 | 提问卡片改写为 ⏱ 已超时：`问题：(未作答)` + 已转回网页端 |
| 超时后又发消息 | ℹ️ 之前的“输入答案”已超时，会话已切回原来的 DSH 会话；这句话会照常发给它 |
| 点已失效的卡片 | ℹ️ 已超时并转回 DSH 网页处理，这张卡片已失效 |

卡片有四种终态，全部通过消息更新接口原地改写（选项按钮不再保留）：

| 状态 | 标题 | 内容 |
|---|---|---|
| 点了选项 | ✅ 已作答 | `问题：答案`（多选以顿号连接） |
| 输入了文字 | ✅ 已作答 | `问题：答案（输入）` |
| 进入输入模式 | ⌨️ 等待你输入答案 | `问题：(等待输入)`，无按钮 |
| 超时 | ⏱ 已超时 | `问题：(未作答)` + 已转回 DSH 网页端 |
| 授权 | ✅ 已允许 / ❌ 已拒绝 | 工具 + 原因 + 结果 |

标题下还有一行小字标出工作区 › 会话，方便回溯是哪条任务。

所有对外消息都带 `工作区标题 › 会话标题`（来自 workspace 注册表与 session title 服务），
取不到标题时才退回 `未命名会话 · <id>`；会话名放在卡片标题下的副标题里。

**为什么必须是 2.0**：1.0 卡片的 `markdown` 元素不渲染 `>` 引用、`###` 以下标题和表格，
而 `msg_type: text` 完全不渲染 markdown。2.0 的 `markdown` 元素支持 CommonMark 全集
（标题 1–6、引用、代码块、表格、`<hr>`），限制是每张卡 200 个元素、单个 markdown 元素最多
4 张表（每表显示 5 行，超出由客户端分页）。2.0 需要飞书客户端 7.20+，低于该版本会显示升级提示。

飞书的 `Typing` 是**表情反应**而不是原生的“对方正在输入”：飞书没有给机器人提供输入状态，
给消息加反应是唯一可见的进度标记（hermes 也是这么做的）。需要应用有消息 reaction 的写权限；
没有权限时只是没有徽标，不影响收发。

## 连接方式

### 扫码创建（推荐）

1. 设置 → 飞书 IM →「生成连接二维码」
2. 飞书手机端扫码，按提示确认
3. 页面自动拿到凭据、写入本机、校验机器人身份

用的是开放平台的设备码注册流程（`accounts.feishu.cn/oauth/v1/app/registration`，
`archetype=PersonalAgent`），创建出来的应用已带消息权限，不需要手动勾选。这条接口不在飞书公开
文档里，可能随平台演进；失败时界面会退回到手动填写。

### 手动填写

已有应用时直接填 App ID / App Secret，但需要自己配：

- 开启「机器人」能力
- 权限：`im:message`、`im:message:send_as_bot`、`im:resource`、`im:chat`
- 事件：`im.message.receive_v1`（**长连接**）
- 回调：`card.action.trigger`（**回调配置**页，不是事件配置页；同样用长连接）
- 发布一个应用版本（权限与回调不发布会不生效，按钮点了会报 `200340`）

## 会话与消息路由

- 每个飞书会话对应一个 DSH 会话，存在 `state.json` 的 `chatSessions` 里；
- 新会话的工作目录取 DSH 的默认工作目录，可用 `/new` 另开一个；
- 飞书消息 id 直接当 prompt request id，飞书重投同一事件时不会重复开轮；
- 只有允许列表里的 open_id 能触发；扫码授权的人会自动进入列表；
- 机器人自己发的消息不处理；群聊里必须 @ 到它。

## 安全模型

- App Secret 只存在 `<DSH_HOME>/feishu-im/state.json`，权限 `0600`，不回传浏览器、不写进 `cordis.patch.yml`。
- 设置页的接口是 DSH 的 exact Fetch 路由（`/api/feishu-im/*`），只有本机已认证的 owner 浏览器能访问。
- 飞书侧按 `open_id` 允许列表过滤；列表为空时接受第一个来消息的人并把他设为唯一使用者（扫码创建流程会
  自动填好，手动模式才有这一步）。
- 「允许在飞书里指挥 DSH」关闭时，飞书只收通知，不接指令。
- 危险操作仍走 DSH 的审批策略；审批卡片只是把同一次请求搬到手机上回答。
- 同一个飞书应用不要在别处（比如 hermes 网关）同时开长连接：飞书会把事件随机投给其中一条。

## 状态文件

```
<DSH_HOME>/feishu-im/state.json    # 0600，凭据 + 允许列表 + 会话映射 + 通知开关
```

「断开连接」会清空它并使缓存的 tenant token 失效。

## 排障

打开宿主追踪（默认关闭）：

```bash
DSH_FEISHU_IM_TRACE=1 dsh web
```

会往 `<DSH_HOME>/feishu-im/host-probe.log` 写：路由注册、长连接起停、turn 事件、通知发送结果、
卡片点击。常见症状：

| 症状 | 多半原因 |
|---|---|
| 设置页报 HTTP 404 | 宿主插件没激活，或 `/api/feishu-im/*` 路由没注册 |
| 长连接 `gateway-failed` | App Secret 不对，或应用没发布版本 |
| 卡片点了报 `200340` | `card.action.trigger` 没配成回调 + 长连接，或没发布版本 |
| 飞书发消息没反应 | 会话正忙（会回“已排队”），或发送者不在允许列表 |
| 没有 Typing 徽标 | 应用缺消息 reaction 写权限（`im:message.reactions:write_only` 一类），其余功能不受影响 |
| 名字是“未命名会话” | 该会话还没有生成标题；发一条消息后标题服务会补上 |
| 卡片提示“升级客户端” | 客户端低于 7.20，不支持卡片 JSON 2.0 |
| 表格只显示 5 行 | 2.0 的 markdown 表格本身限制每表 5 行，其余由客户端分页 |

## 开发

```bash
node --check index.js && node --check client.js && node --check lib/*.js
node scripts/render-smoke.mjs     # 组件树冒烟（自带 React 桩）
node scripts/render-ssr.mjs       # 真 React 19 渲染每个页面状态（需 ../.tmp-react）
```

安装（推荐，从 npm）：

```bash
plugin_manager install_bundle dsh-plugin-feishu-im
# 或
npm i -g dsh-plugin-feishu-im
```

本地改动想先试，用 tarball：

```
plugin_manager install_bundle /absolute/path/to/dsh-plugin-feishu-im-<version>.tgz
```

打包用 `npm pack`：profile 里用 tarball 安装才会把 `qrcode` 与 `@larksuiteoapi/node-sdk` 一起装上；
目录直装只会链接过去，运行期依赖解析不到。
